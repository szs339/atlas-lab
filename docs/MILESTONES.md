# Implementation milestones

## 1. Working backbone — implemented locally

- Seven primary pages plus project details, CV utility, and a 404 page.
- One People page for current researchers and alumni.
- Shared content and stable IDs across projects, papers, news, people, awards, resources, and thesis ideas.
- Optional sections and draft visibility.
- Editable page wording, navigation labels and shared interface text.
- Editable content forms and a GitHub Pages publishing workflow.
- Responsive starter design, search/filter controls, content validation, and integration tests.

Acceptance achieved: local production build and 17 automated tests pass. Source is ready to place in a GitHub repository. Remote publishing and the editor login are configured in source but not connected or verified yet.

## 2. Connect and exercise the publishing workflow

Create the GitHub repository, enable Pages Actions publishing, authorize Pages CMS, and run the first account-connected acceptance test in TESTING.md. Confirm a saved content edit reaches the actual site.

## 3. Populate reviewed lab content

Import the verified current/alumni roster, publications, public awards, additional projects, and selected news. Add the public CV. Review project descriptions and thesis directions. Confirm linked records and former contributor groupings with real content.

## 4. Refine the design and launch

Adjust typography, spacing, project imagery, homepage emphasis, and approved institutional branding. Test real content on phones and desktops, perform a deeper accessibility pass, and review all public links and factual claims.

## 5. Maintain and extend when needed

Use the CMS for routine content. Review dependencies periodically. Add reviewer workflows, pagination/search indexing, redirects, a Penn State hosting destination, or other features when there is a concrete need. The current content structure supports later design changes without re-entry.
